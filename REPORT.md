## 1. Какой источник данных выбран и почему

**Официальный XML Национального банка Молдовы (НБМ):**
`https://www.bnm.md/ru/official_exchange_rates?get_xml=1&date=ДД.ММ.ГГГГ`.

Почему не бесплатный API курсов:

1. Это законный официальный курс в Молдове. У бесплатных API курса MDL обычно нет, либо нужен
   ключ, и курс у них не официальный.
2. Ключ, регистрация и лимиты не нужны.
3. Запрос идёт по конкретной дате, поэтому требование «выходные и праздники» проверяется
   естественно.
4. Разбор XML (номинал, битые элементы, некорректный ответ) — содержательный объект для
   unit-тестов.

Поведение источника проверено вживую 18.11.2026 (`specs/001-currency-converter/research.md`, R2):

| Запрос | Ответ |
|---|---|
| рабочий день | HTTP 200, 40 валют |
| выходной | HTTP 200, курс пятницы, `Date` = запрошенная дата |
| завтра | HTTP 200 (публикуется после ~13:00) |
| послезавтра, 1990 год | HTTP 404, пустое тело |

У JPY и UZS номинал 100. После первого прохода анализа источник переключён с `/en/` на `/ru/`:
данные те же, а названия валют русские, как и интерфейс.

## 3. Что агент собрал корректно с первой попытки

Код прогонов 1–3 (все задачи T001–T023) прошёл все проверки без ручных правок:

- **≈90 проверок по контрактам** (`contracts/core-api.md`, `bnm-source.md`):
  - точные имена, сигнатуры и сообщения на русском;
  - формула конвертации с номиналом и все примеры из контракта (`100 USD = 1833,83 MDL`,
    `100 EUR = 17499,93 JPY`);
  - разбор настоящего XML, коды ответов 200/404/5xx и сетевые ошибки;
  - откат по датам: ровно 11 запросов, `NoRatesError`;
  - атомарный кэш, `last_error`, `LoadResult.warning`.
- **Дымовые тесты окна с поддельным сервисом:**
  - автозагрузка при старте;
  - активность кнопки и Enter;
  - сообщения валидации;
  - офлайн-предложение сохранённого курса;
  - заметка о повреждённом кэше не стирается.
- **quickstart, сценарии 1–10 на живом источнике** (`docs/quickstart/T024-results.md`):
  конвертация в обе стороны, курс за воскресенье, работа без сети с сохранённым курсом и без
  него, повреждённый кэш.
- README на русском и все задачи помечены в `tasks.md` честно, только выполненные.

Тесты фазы 8: из 190 тестов первой версии 167 были корректны сразу (5 файлов из 6).

**Ручные правки кода (Claude Code), всё в одном коммите `0520ae1`:**

- удалена недостижимая ветка в `formatting.status_line`;
- тест `test_fetch_xml_404_status_response` переписан по контракту;
- добавлены регрессионные тесты для пунктов 7, 8 и 10.

Вручную, потому что Antigravity не смог доделать: недельная квота Gemini исчерпана (сброс
через 165 ч), GPT-OSS выдал ложный отчёт, Claude Sonnet 4.6 остановился. Других ручных правок
кода приложения не было.

**Ошибки спецификации (мои, не агента):**

- В первой версии `spec.md` был неверный допуск обратной конвертации «±0,01». Найден при
  планировании, затем снова при анализе: 0,10 MDL → EUR → MDL расходится на 0,10. Исправлен.
- Контракт требует сообщение `"Нет связи с bnm.md: {detail}"`. Агент выполнил его буквально,
  и пользователь видит технический текст вроде `<urlopen error [WinError 10061]…>`. Это
  противоречит принципу II конституции («понятное сообщение»). **Расхождение оставлено
  и зафиксировано.**
- Нарушение процесса: поправка конституции v1.1.0 закоммичена вместе с другими файлами, хотя
  раздел Governance требует отдельного коммита (замечание N2 второго прохода анализа).

**Вывод.** По одной спецификации агент другой компании собрал работающее приложение без ручных
правок кода на этапе реализации. Это и проверялось в лабораторной. Расхождения появились в
краевых сценариях, которые спецификация описывала одной фразой (поведение 2: «выбор
очищается»). Агент реализовал их по-своему (подставлял USD), а мои проверки по контрактам
этот случай не покрыли — его нашло только независимое ревью. Самыми ненадёжными оказались не
код, а отчёты агентов: «расхождений нет» от Gemini и вымышленный список правок от GPT-OSS.
Поэтому каждый прогон проверялся по фактическому диффу и тестам, а не по ответу агента.
